Генерация изображений идёт через встроенный инструмент Codex `image_gen`, который
работает на общей **подписке ChatGPT** (auth.json режима `chatgpt`) — без ключа
OpenAI и без оплаты за картинку. Мы драйвим `codex exec` из песочницы, он рисует и
сохраняет PNG, скрипт кладёт его в workspace.

## Как запустить

Бэкенд — bash-скрипт, запускается через **forkd**: `dispatch_to_connector` target
`"forkd"`, kind `"forkd.run"`, payload:

```
{ "skill_path": "imagegen/scripts/imagegen.sh",
  "interpreter": "bash",
  "args": ["--prompt", "<готовая спека, см. ниже>",
           "--out", "image.png",
           "--size", "1024x1024"],
  "timeout_secs": 300 }
```

- `--prompt` (обязателен) — собранная тобой спека (см. «Как строить промпт»).
- `--out` — имя файла в workspace (по умолчанию `image_<время>.png`).
- `--size` — размер gpt-image-2: `1024x1024` (квадрат, быстрее всего),
  `1536x1024` (альбом), `1024x1536` (портрет), `2048x1152` (2K), `auto`. Стороны
  кратны 16, соотношение не круче 3:1.
- `--image <путь>` — входное изображение (референс или объект правки), можно
  несколько раз. Роль каждого опиши словами в `--prompt` («Image 1 — референс
  стиля», «Image 2 — объект правки»).

Скрипт печатает в stdout сводку: `[out] <путь>`, `[size]`, `[src]`. Таймаут ставь
~300 с (одна картинка обычно 1-2 минуты); на батч из нескольких — вызывай скрипт
по разу на картинку и подними таймаут.

## Как отдать результат пользователю

Картинка лежит в workspace по пути из `[out]`. Отправь её в чат командой
**`chat.send_file`**: `dispatch_to_connector` target — id телеграм-коннектора,
kind `"chat.send_file"`, payload `{ "path": "image.png", "caption": "<подпись>" }`.
Изображение уйдёт как **фото с превью** (не документом); `caption` — короткая
подпись, необязательно. Не вставляй байты картинки в текст ответа — только по
ссылке через `chat.send_file`.

## Как строить промпт (это половина успеха)

Диффузионная модель слушает структуру, а не поток сознания. Собери спеку из
помеченных строк — бери только нужные, порядок «сцена -> субъект -> детали ->
ограничения»:

```
Use case: <слаг из таксономии ниже>
Primary request: <главная суть запроса пользователя>
Subject: <главный объект>
Scene/backdrop: <окружение, фон>
Style/medium: <фото / иллюстрация / 3D / флэт-вектор / акварель ...>
Composition/framing: <широко/крупно/сверху; расположение, негативное пространство>
Lighting/mood: <свет и настроение>
Color palette: <палитра>
Text (verbatim): "<точный текст на картинке, если нужен>"
Constraints: <что обязательно сохранить>
Avoid: <чего не должно быть: логотипы, водяные знаки, лишний текст ...>
```

Насколько дополнять:
- **Промпт уже подробный** — приведи в структуру, ничего своего не выдумывай.
- **Промпт общий** — добавь со вкусом только то, что реально улучшит результат
  (кадрирование, уровень полировки, конкретику сцены). Не подсовывай лишних
  персонажей, брендов, слоганов, палитр, которых пользователь не просил.

Мелочи, которые сильно помогают:
- Укажи назначение (обложка, мокап приложения, реклама, инфографика) — это задаёт
  режим и уровень детализации.
- Для фотореализма — язык камеры (объектив, ракурс, глубина резкости, свет).
- Точный текст бери в кавычки и требуй дословности; для трудных слов диктуй по
  буквам. Модель всё равно врёт в длинном тексте — держи надписи короткими.

Таксономия (слаг в `Use case:`): `photorealistic-natural`, `product-mockup`,
`ui-mockup`, `infographic-diagram`, `scientific-educational`, `ads-marketing`,
`productivity-visual`, `logo-brand`, `illustration-story`, `stylized-concept`,
`historical-scene`. Для правок: `text-localization`, `identity-preserve`,
`precise-object-edit`, `lighting-weather`, `background-extraction`,
`style-transfer`, `compositing`, `sketch-to-render`.

Больше принципов и готовых рецептов — в `references/prompting.md` и
`references/sample-prompts.md`. Читай их, когда задача нетривиальная.

## Генерация или правка

- Нет входной картинки, или входные даны только как **референс** стиля/настроения
  -> это **генерация**.
- Просят изменить существующее изображение, сохранив его части -> **правка**:
  передай файл через `--image` и в спеке жёстко перечисли инварианты («меняй
  только фон; субъект и его края не трогай»), повторяй их при каждой итерации.
- **Часто с нуля выходит лучше, чем правкой.** Если правка требует переписать
  большую часть кадра (сменить ракурс, стиль, композицию), не насилуй edit —
  сгенерируй заново по хорошему промпту. Правкой имеет смысл идти, когда надо
  сохранить узнаваемость (лицо, конкретный продукт, точный layout).

## Прозрачный фон

Прямой прозрачности встроенный инструмент не даёт. Проси плоский однотонный фон
хромакея (`#00ff00`, для зелёных субъектов `#ff00ff`), без теней и градиентов, с
запасом по краям — потом фон можно снять локально. Для сложных краёв (волосы,
мех, стекло, дым) чистого выреза не выйдет — честно предупреди пользователя.

## Итерации и проверка

Сгенерил — посмотри глазами: субъект, стиль, композиция, точность текста,
соблюдены ли инварианты и `Avoid`. Правь по одному изменению за раз и перепроверяй.
Не молоти десятки вариантов — модель платная по подписке, но не бесплатная по
времени пользователя.

## Если не работает

Скрипт вернёт ненулевой код и причину в `stderr`:
- «codex binary not found» — на стенде не установлен Codex CLI (нужен для
  подписочного имейджгена). Скажи пользователю честно, не выдумывай картинку.
- «auth_mode is not chatgpt» — codex залогинен не по подписке; скрипт отказывается,
  чтобы не списать деньги с API-ключа.
- «image was not produced» — модель не сохранила файл; повтори с более чётким
  промптом.
Докладывай ошибку из `stderr` как есть.
